**Organization**: Tasks are grouped by user story so each story can be implemented and verified as an independent increment after its declared prerequisites.

## Format: `[ID] [P?] [Story] Action with exact path`

- **[P]**: Safe to execute in parallel after the phase prerequisites because the task changes different files and does not depend on unfinished work in the same phase.
- **[US1]`-`[US5]**: User story ownership; these markers appear only in story phases.
- Each task names its exact target path, explicit prerequisite where needed, and smallest relevant validation.

## Implementation Strategy

1. Complete Setup and Foundational in dependency order; do not expose a route or screen before database/domain/public-boundary invariants are executable.
2. Implement each story test-first: add the listed failing tests, confirm the expected failure, make the smallest implementation diff, and run only the targeted command before moving on.
3. Deliver US1 first because it establishes discovery and the shared read-only card. Then implement US2 identification and US3 selection; each remains fixture/emulator-backed and independently demonstrable after its declared prerequisites.
4. Add P2 stale-result and session-safety hardening, then run cross-cutting contract, architecture, production-gate, responsive, visual, and end-to-end validation.
5. Keep the production machine protocol boundary fail-closed. Development and tests use only the standalone emulator and deterministic application-owned fixtures; production emulator/fixture/legacy-QR modes remain forbidden or disabled until separately verified inputs exist.

## MVP Scope

The minimum complete machine-selection flow is **Phase 1 Setup + Phase 2 Foundational + US1 + US2 + US3**. Discovery alone is not a usable MVP: the customer must be able to find candidates, identify the exact physical machine, inspect refreshed price/status, and confirm a current `ONLINE` machine into the typed navigation handoff. US4 and US5 are P2 hardening increments required before a production-ready release but are not prerequisites for demonstrating the controlled MVP flow.
