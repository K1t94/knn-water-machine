  ## Цель

  Создай `specs/005-referral-program/tasks.md` с небольшими, проверяемыми и
  dependency-ordered задачами для реализации:

  - одного стабильного уникального промокода на пользователя;
  - referral deep link;
  - pending promo при регистрации;
  - immutable referral relationship;
  - post-registration применения промокода;
  - eligibility lock для будущей первой успешной покупки;
  - welcome-бонуса 10 000 мл для нового пользователя;
  - inviter-бонуса 5 000 мл;
  - durable bonus entitlements;
  - идемпотентной доставки бонусов через существующий wallet;
  - PostgreSQL recovery worker;
  - authenticated referral API;
  - mobile MobX/RxJS integration;
  - минимального referral UI;
  - regression и acceptance validation.

  Приглашённый получает только welcome-бонус. Не добавляй отдельный
  referral-бонус приглашённому.

  Существующие пользователи должны получить промокоды, но не должны получать
  welcome-бонус задним числом.

  ## Формат задач

  Для каждой задачи:

  - укажи уникальный ID в формате `T001`, `T002` и далее;
  - укажи Phase;
  - укажи связь с пользовательской историей `US1`–`US4`, когда применимо;
  - используй `[P]` только для действительно параллельных задач;
  - укажи точные создаваемые или изменяемые файлы;
  - укажи зависимости от предыдущих задач;
  - добавь минимальную команду проверки;
  - сформулируй наблюдаемый критерий завершения;
  - укажи, если задача требует настоящего PostgreSQL или Redis;
  - не объединяй в одну задачу несвязанные schema, backend, mobile и validation
    изменения;
  - сохраняй один логический diff на задачу, насколько это практически возможно.

  Не помечай `[P]` задачи, которые изменяют один файл, одну миграцию, Prisma schema,
  composition root, registration transaction или общий OpenAPI snapshot.

  ## Dependency order

  Обеспечь следующий порядок:

  1. Domain и configuration до Prisma repository.
  2. Prisma schema и migration до persistence implementation.
  3. Relationship concurrency до bonus delivery.
  4. Durable entitlement и recovery до registration integration.
  5. Registration integration до public API acceptance.
  6. Public API до mobile API/store/flow.
  7. Mobile data flow до UI.
  8. Все implementation phases до full regression.

  Если внутри Phase есть обязательный более строгий порядок, зафиксируй его через
  явные зависимости задач.
